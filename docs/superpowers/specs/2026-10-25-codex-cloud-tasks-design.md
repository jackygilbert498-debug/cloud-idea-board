## 用户目标与已确定的约束

在云端构思板增加独立的「Codex 任务」入口。用户在手机或电脑登录现有网站，选择项目、填写任务与验收要求、点击发布；云端 Codex 自动接收并执行，在网站回看响应和代码变更。

## 接收执行的实现选择

采用官方的 GitHub PR 委派路径。每个任务建立一个专用分支和 PR，随后由与 Codex 已关联的用户身份发布 `@codex` 评论，请其在该分支完成任务并运行项目验证。Codex 在自己的云端环境执行，使用该用户现有套餐的云端任务额度。

官方已明确 PR 评论可以启动编码任务；当前资料没有充分说明通过用户授权代发的评论是否必然触发，故第一阶段必须先做最小云端验收，不能仅以 GitHub 接口返回成功作为自动执行成功。

### 第一步：最小端到端能力验证

1. 只读确认当前 GitHub 用户身份、目标仓库权限，以及仓库是否已连接 Codex 云端环境。
2. 用该用户身份在独立验收分支创建一个低风险测试 PR，并通过 GitHub API 评论 `@codex`，请求仅改一份验收 Markdown、运行验证、将结果推回该分支。
3. 确认 Codex 实际响应，产生云端任务链接或明确接收记录，并检查请求的变更确实出现在测试分支。保持 PR 待审查，不自动合并。
4. 如果 Codex 要求连接账号或建立云环境，提供对应官方设置入口；完成连接后重试。若该账号/集成不支持这种代发路径，暂停后续实现并报告真实限制；不擅自转成 API 计费，也不上传本机 ChatGPT 登录凭据。

## 网站体验

- 桌面顶部导航和手机菜单增加「Codex 任务」。沿用现有登录，不再为这个入口要求另一套邮箱密码。
- 任务表单：任务标题、项目、任务描述、验收要求。第一版默认只配置当前 `cloud-idea-board` 项目；更多 GitHub 仓库由服务端明确配置后出现，浏览器不能提交任意仓库地址或本机路径。
- 允许手动填写任务，支持将现有构思记录的文字带入表单；点击发布才产生外部任务。
- 列表显示任务标题、目标项目、发布时间、最近同步时间和有证据支持的当前状态。详情展示原始要求、Codex 回复，以及 PR / 云端任务链接。
- 发布前显示仓库可见性；公开仓库会显示「任务内容将发布到公开 GitHub PR」。不把现有卡片、截图或其他记录自动附送到 GitHub。
- 同一任务可在原 PR 上追加指令。每次追加是一次明确发送动作，不会因页面刷新或状态同步自动重复触发。
- 手机页面使用现有 Emil 风格，按钮点击区至少 44px，输入至少 16px；保留焦点返回、键盘操作和账号切换隔离。

## 云端组件与数据流

`手机发布 → Netlify 鉴权并保存任务 → GitHub 专用分支/PR/委派评论 → Codex 云端执行 → GitHub 结果同步 → 手机查看`

新增单独的任务记录，与人工构思阶段分开存储。任务包含所有者、稳定请求 ID、目标项目、不可变的初始任务、PR 号/分支/评论 ID、最近同步时间、错误信息、外部链接。回复和后续指令为追加记录，避免覆盖原始要求。

浏览器沿用 Supabase 会话。Netlify 验证令牌，并从可信认证结果取得 user ID；服务端显式授权的用户才可使用 GitHub 委派。Supabase RLS 只允许任务所有者读取自己的记录，浏览器不直接写入执行状态或外部资源标识。

实施默认（由实施者提出，用户可调整）：第一版仅用户本人指定的一个 Supabase 账号可派发任务，映射到本人已关联 Codex 的 GitHub 身份，消耗本人的套餐额度。其他站内账号继续使用原看板，不共享该 GitHub 身份、任务记录或额度。多用户分别绑定身份与计费不在第一版范围。

GitHub 授权凭据仅保存在服务端，采用与 Codex 关联的用户身份授权；不假定 App bot 身份可以代替用户触发。运行时使用仅能访问已配置仓库的专用凭据，不能把当前本机 GitHub CLI 的广泛授权直接复制成生产环境凭据。具体安全录入方式在部署时根据现有账号连接确定，密钥不经聊天或前端传递。

## 可重试与状态的边界

- 浏览器产生稳定请求 ID；数据库唯一约束防止双击、超时重试制造重复任务。每阶段持久化外部资源 ID；恢复时先查已有分支、PR 或带任务标记的评论，再决定是否创建。外部请求结果不确定时显示「正在核对发布结果」，不盲目重发 `@codex`。
- 分支按任务 ID 独立，初始提交只增加任务标记/需求文件，使 PR 具有实际差异；已有项目代码由 Codex 在该分支修改。该需求文件是任务记录的一部分，不做空 PR 假设。
- GitHub 创建成功只标记「已发布，等待 Codex」。收到可信 Codex 回复后显示「Codex 已响应」。只有有明确结果证据时显示「有结果，待验收」；PR 合并标记「已合并」，关闭标记「已关闭」。不伪造运行百分比或把 👀 表情当成执行完成。
- 平台能同步 GitHub 已公开提供的回复、提交和 PR 检查结果；第一版不承诺完整复制 Codex 云端内部日志。云端任务链接提供深入查看入口。
- 有限频率的服务端同步与打开页面时的补查共同工作，电脑和手机离线不影响 Codex 的执行。同步失败保留最后可信状态并显示时间，不清空任务或擅自标记失败。
- 签名校验后的 GitHub webhook 可用于及时更新；实施者可根据既有 Netlify 能力选择 webhook 加补查或定时同步，需保证重复投递不会生成新任务、不会因机器人回复递归派单。
- 没有 GitHub 授权、Codex 未连接、额度不足、接口限流、权限变化时，显示可操作的具体状态。失败的派发可以恢复，已开始的云端工作不自动重复。

## 自动化的权限范围

新系统按用户发布的请求创建任务分支、PR 和委派评论。云端任务可在对应分支修改代码并验证；默认交付可审查结果，不自动合并主分支或部署线上。取消平台任务不等于已经停止云端执行；如果没有官方停止接口，界面提供云端任务入口并准确说明。

项目范围限定为 GitHub 中已连接 Codex 的代码项目；仅在本机存在且尚未上传的文件不能由关机后的云端读取。更多任务类型或团队账号可后续扩展。
