# 云端构思板产品稳定化设计

## 背景与目标

当前版本已经具备个人构思记录、阶段流转、截图、离线草稿、Supabase 账号登录与 DeepSeek 梳理，但发布源、弱网保存、设备会话和数据库不变量仍存在可确认的风险。

本轮目标是把项目从“可用 Beta”提升为可持续发布的个人产品：同一次发布可追溯、保存结果可信、退出行为可解释、数据库约束在并发下成立、关键操作可通过自动化和真实浏览器验收。

用户在 2026-09-05 审阅全面审计后回复“行那交给你处理”，批准按审计建议连续实施，无需在各阶段重复确认。

## 方案选择

评估过三种路径：只修线上报错的最小补丁速度最快，但会保留发布漂移和数据不一致；重建成完整团队任务平台能一次扩展权限模型，但明显超出当前个人构思板需求；本设计选择中间路径——保留现有 React、Supabase、Netlify 和视觉结构，只加固个人产品所需的发布、会话、数据和交互边界。代价是团队管理、语音和桌面浮窗继续留到真实需求出现后再设计。

## 范围

### 本轮实现

1. 将公开 GitHub 仓库定义为唯一发布源，建立 CI、Netlify 质量门禁、固定 Node 版本和发布版本标识。
2. 登录页提供“在这台设备保持登录”，保存邮箱但不保存密码；密码继续交给浏览器密码管理器。
3. 增加个人账号页：显示邮箱和当前设备会话方式，支持修改密码、普通退出、退出所有设备、退出并清除此账号的本机缓存与草稿。
4. 保存超时进入“结果待核对”，不立即回滚；迟到成功自动确认，明确失败才回滚；并发操作使用计数而非单一布尔状态。
5. 数据库以增量迁移修复焦点并发上限、附件 RLS、不安全的迁移重跑、附件排序事务和 AI 用户级配额。
6. 附件使用 `pending / ready / deleting` 状态收敛跨 Storage 与数据库的不一致；仅 `ready` 对用户可见，客户端在加载时修复过期中间状态。
7. DeepSeek 模型配置显式校验，认证发生在正文解析前；增加用户级每日额度、结构化无敏感信息日志和清晰错误分类。
8. 补全弹层焦点管理、移动端粘贴反馈、控件可访问名称、加载状态语义、基础字号、对比度和触控面积。
9. 用行为测试替代仅匹配源码文本的发布契约，并完成配置态构建、预览部署和真实浏览器验收。

### 本轮不实现

- 团队、层级、管理员用户后台和成员权限。
- 浏览器直接录音、付费语音转写或音频附件。
- 系统级置顶浮窗；后续优先评估 PWA 的窄屏“今日焦点”模式。
- 删除、重建或覆盖已有 Supabase 数据。

## 设计决策

### 1. 唯一发布源与质量门禁

`C:\Users\zfy20\Desktop\任务看板公开仓库` 及其 GitHub remote 是唯一发布源。历史目录 `任务看板\云端部署` 只保留为迁移前快照，不再人工双向复制。

GitHub Actions 和 Netlify 使用同一个 `verify:release`：Lint、TypeScript、单元/回归测试、必要环境检查、生产构建、产物行为检查。CI 使用无权限测试占位值构建完整前端；生产发布必须由 Netlify 注入真实公开 Supabase URL 与匿名密钥。函数密钥永不进入 GitHub Actions 或浏览器构建。

Node 使用 22 主版本。构建产物暴露 `VITE_BUILD_SHA`，页面账号区展示短 SHA，函数日志记录平台提供的 deploy context/SHA。

### 2. 登录、会话和个人账号

认证存储模式只有两种：

- `persistent`：Supabase session 使用 `localStorage`，浏览器重启后继续登录。
- `session`：Supabase session 使用 `sessionStorage`，浏览器会话结束后重新登录。

登录页默认勾选“在这台设备保持登录”，并说明仅适合私人设备。勾选时保存经过 trim 的邮箱和模式；取消时删除已记邮箱，绝不自行保存密码、access token 或 refresh token。

账号页不引入 profile 表。修改密码直接使用当前 Supabase Auth 会话；普通退出保留本机草稿，显式的“退出并清除本机数据”只清除当前 user ID 的 board/draft 命名空间和内存签名 URL，绝不调用 `localStorage.clear()`。远程登出失败时不清理本机数据。

### 3. 保存可信度

既有卡片保存流程为：乐观更新 → 12 秒内确认则完成 → 超时则标记 `pending_confirmation` 并保持乐观状态和草稿 → 原请求迟到成功后确认 → 原请求明确失败后回滚。

“重新核对”只重新读取云端，不重复提交。每张卡使用 mutation version 防止旧响应覆盖新操作；全局保存指示器由活动操作计数派生，避免较早请求结束时错误地隐藏较晚请求。

创建继续不做强制超时；客户端为每次创建生成稳定 request UUID 并写入草稿，数据库以 `(user_id, client_request_id)` 唯一约束保证同一创建可安全重试。

### 4. 数据库与附件一致性

新增单一增量迁移，包在事务和迁移 advisory lock 中：

- 焦点触发器在计数前获取当前 user ID 的事务锁，同用户并发操作最多保留 3 条焦点。
- 附件 INSERT/UPDATE 同时验证 `card_id` 归属和 `object_key` 的 user ID 前缀。
- `attachments` 增加 `state`、`updated_at`；旧数据回填为 `ready`。
- 创建附件先写 `pending` 元数据，再上传对象，再置 `ready`；删除先置 `deleting`，再删对象和元数据。
- 排序改为单次数据库 RPC，在事务内验证传入 ID 集合正好等于该卡片所有 `ready` 附件。
- 为 AI 使用量增加每用户每日计数 RPC，默认额度由函数环境变量控制。

完整 `schema.sql` 同步最终状态并使用确定性的 `drop policy if exists / create policy`，保证初始化脚本可重跑。历史迁移补上事务、迁移锁和表限定的约束检测，但不改变已应用迁移的业务含义。

### 5. AI 函数

Bearer token 先校验并获取 user ID，再解析正文。`DEEPSEEK_MODEL` 必填且仅允许当前支持的 `deepseek-v4-flash` 或 `deepseek-v4-pro`；部署前先设置为 `deepseek-v4-flash`。

认证后调用 Supabase RPC 消耗用户当日额度，再调用 DeepSeek。日志仅包含 request ID、deploy SHA、模型、结果分类、HTTP 状态和耗时，不包含邮箱、原文、token、API key 或签名 URL。平台 IP 限流继续作为边缘防护，数据库额度负责账号级成本约束。

### 6. 界面与可访问性

保留当前冷静、轻量的蓝灰视觉体系，不进行品牌重做。界面令牌使用：画布 `#f5f7fa`、纸面 `#ffffff`、主文字 `#202735`、次文字 `#5f6b7a`、弱文字 `#707b8a`、强调 `#596fd8`、错误 `#a4473d`。系统中文无衬线字体保持不变。

编辑器和图片查看器共享无依赖 focus-trap：打开时保存触发元素、聚焦首个目标、Tab/Shift+Tab 留在最上层弹层、Escape 关闭、关闭后恢复焦点。弹层有可见标题和 `aria-labelledby`。

普通说明文字最低 12px；移动端常读输入最低 16px，主要触控目标 44px。移动端截图粘贴必须给出明确提示且不静默吞输入。阶段切换使用按钮筛选语义，菜单暴露展开状态，加载过程使用 `role=status`。

### 7. 测试与验收

所有行为修改遵循测试先行。最低自动化覆盖：

- 会话模式、记住邮箱、按 user ID 清理本机状态。
- 保存超时、迟到成功、迟到失败、并发操作计数和创建 request UUID。
- 完整 schema/两份历史迁移/新增迁移的串行重复执行。
- 焦点上限、附件归属、附件状态机、排序 RPC 和 AI 配额的数据库行为。
- 个人账号页、登录勾选、弹层焦点循环、移动粘贴反馈和加载语义。
- AI 模型校验、认证顺序、配额错误、429、超时、无效 JSON和结构化日志字段。
- 发布环境缺失时门禁失败，测试占位配置和真实 Netlify 配置都构建完整应用。

最终验收包括：全套测试、Lint、类型检查、生产构建、生产依赖审计、secret scan、Netlify 预览、响应头检查，以及登录后创建/保存/刷新/AI梳理/附件/退出的真实浏览器链路。无法验证的外部项必须标为 `pending_external`，不能算通过。

## 失败处理与回滚

- 代码改动只在 `codex/product-stabilization` 隔离分支进行；历史目录不重置、不清理。
- 数据库迁移只做加列、函数、触发器、策略和回填，不删除用户数据；执行前记录数据库状态，失败由事务回滚。
- Netlify 先发固定预览；预览验收通过后才更新正式站点。
- 如果 Supabase 或 Netlify 授权状态无法自动确认，代码和本地验证仍可完成，但外部迁移/发布标记为 `pending_external`。
